## B. Files modified

`README.md` was the only pre-existing source file modified. It now documents setup,
fictional accounts, checks, authorization, deployment boundaries, and limitations.

## C. Database schema

- Supabase's `auth.users` supplies the User entity.
- `profiles`: private user profile with creation/update timestamps.
- `businesses`: tenant root, slug, status, London timezone.
- `business_memberships`: non-null user/business foreign keys, composite primary
  key, independent role and active/revoked state.
- Enums: `business_role`, `business_status`, `membership_status`.
- Live membership predicate, profile creation trigger, timestamp triggers, narrow
  grants, RLS enabled/forced, and restrictive future default grants.

Schema was exercised in a disposable PostgreSQL/PGlite test database. No hosted
database was created or modified.

## D. Authentication

Supabase email/password with confirmed email, HttpOnly cookies, token refresh,
per-request server verification, reset/invitation token handling, password setup,
and global sign-out. No browser administrative credentials. Public registration is
disabled in local configuration. Fictional accounts are provisioned separately.

## E. Tenant isolation

Client IDs/slugs only select a business. The server verifies user identity and live
membership. PostgreSQL independently checks active membership and tenant status for
each statement. Only owners may rename their business; no client may self-provision,
edit memberships/roles/status, or move ownership. Anonymous table grants are absent.
The private boolean helper is search-path hardened and accepts no user-ID argument.

## F. Security tests

31 PostgreSQL policy/constraint tests, 5 server-authorization tests, 8 environment
tests. Coverage includes both directions of cross-tenant reads/writes, own-business
access, unchanged-claims revocation, suspension, anonymous denial, forged metadata,
self-provisioning/escalation denial, multi-business role separation, and profiles.

Also created 14 native pgTAP assertions, two browser smoke tests, and three actual
Supabase authentication browser tests. The native and real-auth tests require Docker.
